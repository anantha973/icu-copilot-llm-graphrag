Core Concepts Explained

GraphRAG (Graph-guided RAG)

Traditional AI searches for matching text documents (Standard RAG). GraphRAG is smarter: it navigates a web of relationships. If a patient takes Metformin, the AI travels along a mathematical edge to find that it treats Diabetes, and checks for contraindications automatically.

Vector Indexing (FAISS)

Medical guidelines are long PDFs. We use Vector Embeddings to turn sentences into coordinates in space. When the AI needs to know about "Low blood pressure protocols," it mathematically finds the closest matching paragraph instantly using FAISS.

Local LLMs & On-Premise AI

Hospitals cannot legally send patient data to OpenAI or Google due to HIPAA. We use Quantized Local Models (like MedGemma inside a GGUF file). These are compressed "brains" that run entirely on the hospital's local laptop/server hardware.

NetworkX & PyVis

NetworkX is the invisible engine mapping the mathematical nodes and edges. PyVis is the renderer that turns those invisible math equations into the beautiful, physics-driven floating bubbles you see on the dashboard.

The Thought Process

The goal was to build a system that is Trustworthy, Secure, and Instant.

  • Trust: Doctors don't trust black-box AI. By grounding the AI in a visual Knowledge Graph (PrimeKG) and citing exact hospital PDFs, the AI proves its reasoning.
  • Security: By enforcing a strictly local architecture (Layer 3), no patient data ever touches the internet.
  • Separation of Concerns: The 4-layer architecture ensures that if the LLM fails, the rule-based Severity Classifier (Layer 3) and raw Vitals display (Layer 4) remain 100% functional.

How to Build This

Building this requires a step-by-step pipeline approach:

  • Step 1 (Data Prep): Download PrimeKG (CSV) and chunk your hospital PDFs using Python's LangChain. Store them in a local FAISS index.
  • Step 2 (Graph Construction): Write a Python script using pandas to find all rows matching your patient's symptoms. Connect them using networkx.
  • Step 3 (AI Binding): Load a `.gguf` language model via llama.cpp. Write a prompt that injects the Graph text and the FAISS text before asking the AI to diagnose.
  • Step 4 (The Web Server): Wrap everything in FastAPI. Expose endpoints like /api/patient/123 that return the AI's response to a beautiful frontend.

The Step-by-Step Breakdown

  • Step 1 (Intent & Entity Recognition): The system identifies key medical entities in the question: "Type 2 Diabetes", "Acute Kidney Injury (AKI)", and "Metformin".
  • Step 2 (The Knowledge Graph - PrimeKG): Instead of guessing, the AI looks at the patient's personalized mathematical graph. It finds the node for Metformin and sees a bright red mathematical edge labeled contraindicates pointing directly to Renal Failure / AKI. The graph proves that Metformin is dangerous here because failing kidneys cannot clear the drug from the body safely.
  • Step 3 (Vector Search - FAISS): The AI needs official hospital policy to back up the graph. It converts the query into a mathematical vector and searches the hospital's indexed PDF guidelines. It retrieves a specific paragraph from the ICU Endocrine Protocol: "Discontinue Metformin immediately if Creatinine > 1.5 mg/dL due to risk of lactic acidosis."
  • Step 4 (Prompt Construction): A hidden super-prompt is built locally behind the scenes:
    Context 1 (Graph): Metformin contraindicates AKI.
    Context 2 (PDF): Stop Metformin if Creatinine > 1.5.
    Task: Answer the doctor safely using only this context.
  • Step 5 (Inference - MedGemma): The local 4-billion parameter model reads the strict context. It generates the final response:

    "CRITICAL WARNING: Do not increase Metformin. The Knowledge Graph indicates Metformin is contraindicated in Acute Kidney Injury. Furthermore, hospital guidelines state Metformin must be discontinued when Creatinine exceeds 1.5 mg/dL (Patient is at 2.5 mg/dL) due to high risk of lactic acidosis. Consider switching to an insulin sliding scale for glucose control."

3. Decision Responsibility Layer

In medical systems, "Who makes the decision?" is critical. Not everything is AI.

Situation Decision Maker Mechanism
Glucose > 400 mg/dL Deterministic Rules If/Else logic engine. Zero latency.
Insulin Dosing Suggestion AI-Assisted LLM suggests based on FAISS guidelines, requires MD approval.
Final Medication Order Physician Only Human-in-the-loop requirement. E-signature.
Blocked Unsafe Action (AKI + Metformin) Graph Hard-Stop Knowledge graph constraint physically blocks UI submission.

8. Event-Driven System Thinking: How Hospital AI Actually Thinks

The system does not "poll" every 5 minutes. It is purely Event-Driven.

  • State Transitions: The ICU Copilot exists in discrete states (Normal, Warning, Critical). Transitions only happen upon events (e.g., lab result arrives).
  • Asynchronous Triggers: A heart rate anomaly triggers a localized Python asyncio task, which does not block the UI from receiving glucose updates.
  • Alert Escalation Chains: If a Warning is not acknowledged in UI within 15 minutes, it elevates to Critical and triggers an SMS gateway API.
  • Temporal Reasoning: The graph holds history. "Glucose is 180" means nothing. "Glucose was 80, now 180 in 20 minutes" triggers an aggressive rate-of-change event.

4. Failure Mode Analysis (Fallbacks)

How real ICU systems are engineered: "What if this layer fails?"

Component: Local LLM Crashes

Impact: Natural language summaries stop.

Fallback: System reverts to Safe-Mode Rules Engine. Basic text alerts ("High Glucose") continue firing. UI grays out AI chat window.

Component: WebSocket Disconnects

Impact: Real-time streaming halts.

Fallback: Client switches to HTTP Long-Polling. UI displays "Degraded Connection" banner.

Component: FAISS Retrieval Fails

Impact: Guidelines unavailable for RAG.

Fallback: LLM appends: "Warning: Operating without guideline vector context." Relies entirely on structured EMR/Graph data.

Component: Monitor Data Corrupted

Impact: Erratic vitals (e.g. HR = 999).

Fallback: Anomaly detection layer drops frame. AI inference paused until 3 stable frames received.
