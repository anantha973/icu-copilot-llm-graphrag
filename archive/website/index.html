§4 — Architecture

Layer-by-Layer Architecture

Built bottom-up for reliability. Each layer has one responsibility — and can fail independently without bringing the system down.

Layer 0 · Foundation

Data Ingestion + Patient State

  • FHIR-format JSON parsed by synthea_parser.py
  • Free-text clinical notes extracted by medgemma_extractor.py using MedGemma 4B
  • Both streams unified into a single PatientState dataclass
  • Single source of truth — all downstream layers read from here
synthea_parser.py · medgemma_extractor.py · PatientState
Layer 1A · Pipeline A

Deterministic Safety + Severity Classification

  • Rule-based vital threshold checks — MAP < 65, SpO₂ < 90, Lactate > 4.0
  • Severity levels: RED / AMBER / GREEN — no probabilistic component
  • Fires before any AI. Critical alerts block AI inference until acknowledged
  • Output is a signed, tamper-evident severity object
severity_classifier.py · Stage 1 rules
Layer 1B · Pipeline B

FAISS Guideline Retrieval

  • NIH + ADA + AHA clinical guidelines indexed offline via guideline_indexer.py
  • all-MiniLM-L6-v2 embeddings — 384 dimensions, cosine similarity
  • Top-3 most relevant guideline chunks retrieved per patient query
  • No network calls at inference time — fully on-premise FAISS index
guideline_indexer.py · FAISS · all-MiniLM-L6-v2 · top-k=3
Layer 2 · Graph Retrieval

PrimeKG Subgraph Retrieval

  • 129,000 biomedical concepts and 8 million relationships (PrimeKG)
  • RapidFuzz entity linking maps free-text drug/disease names to graph nodes
  • 2-hop ego subgraph extracted per condition — reveals cascading relationships
  • drug_disease, disease_disease, and gene_disease edge types traversed
subgraph_retriever.py · PrimeKG · ego_graph(radius=2) · RapidFuzz
Layer 3 · Reasoning

Contextual LLM Reasoning

  • All evidence assembled into a structured XML-tagged prompt by global_kb_retriever.py
  • MedGemma 4B writes clinical summary — domain-tuned for medical language
  • Gemma 4 E4B reasons over graph context — cites specific nodes, surfaces interactions
  • Output includes: severity, drug alert flags, evidence bullets, uncertainty markers
reasoner.py · MedGemma 4B · Gemma 4 E4B · global_kb_retriever.py
Layer 4 · Output

Physician Dashboard

  • FastAPI REST layer serves patient state, alerts, and AI suggestions
  • Real-time ward overview — severity-sorted patient grid
  • Detailed per-patient view with AI explanation and source traceability
  • Physician decision logged — AI never acts without human confirmation
app.py · FastAPI · physician-in-loop · audit trail
⚡

Key architectural property

Layers 0 and 1A are purely deterministic. They cannot be overridden by AI output. If Layer 1A fires a RED alert, the system halts AI inference and surfaces the deterministic alert immediately. The probabilistic layers (1B, 2, 3) only run when the patient is stable enough to warrant deeper analysis.

§6 — AI Pipeline

How the AI Thinks

Seven deterministic steps. Every inference is traceable. Every suggestion is grounded in evidence the physician can inspect.

01

Read Patient State

The unified PatientState object is read — containing parsed vitals, medications, active conditions, and any free-text notes extracted by MedGemma. This is the single ground truth for all subsequent reasoning.

PatientState · synthea_parser · medgemma_extractor
02

Deterministic Safety Check

Before any LLM runs, vital thresholds are evaluated against hardcoded clinical rules. MAP < 65 mmHg, SpO₂ < 90%, Lactate > 4.0 mmol/L — each produces an immediate flagged alert. This layer cannot be overridden by AI output.

severity_classifier.py · Stage 1 · no-LLM
03

Entity Linking to PrimeKG

Each drug and disease name in the patient record is fuzzy-matched to a PrimeKG node using RapidFuzz with a 85% similarity threshold. Unmatched entities are flagged and excluded — preventing graph traversal on hallucinated nodes.

RapidFuzz · threshold=85 · entity_linker.py
04

2-Hop Graph Traversal

For each linked entity, a 2-hop ego subgraph is extracted from the in-memory PrimeKG NetworkX graph. Drug–disease, disease–disease, and gene–disease edges are all traversed. The result is a structured list of biomedical relationships with edge-type labels.

subgraph_retriever.py · ego_graph(radius=2) · NetworkX
05

Guideline Retrieval

In parallel, the patient's conditions are embedded and queried against the offline FAISS index. The top-3 most semantically relevant clinical guideline chunks are retrieved — sourced from indexed NIH, ADA, and AHA protocols.

guideline_indexer.py · FAISS · top-k=3 · all-MiniLM-L6-v2
06

Evidence Assembly + Prompt Construction

Graph context, guideline chunks, severity result, and patient vitals are merged into a structured XML-tagged prompt by global_kb_retriever.py. Every input is labelled by source — the LLM cannot conflate guideline evidence with graph evidence.

global_kb_retriever.py · XML-tagged context · structured prompt
07

LLM Inference + Traceability Output

MedGemma 4B produces the clinical language summary. Gemma 4 E4B reasons over the assembled evidence — citing specific graph node names, flagging drug interactions, explaining severity classification, and marking uncertain inferences explicitly.

reasoner.py · MedGemma 4B · Gemma 4 E4B · citation-aware
🛡️

Hallucination Guard

If entity linking fails (similarity < 85%), the system does not traverse the graph for that entity. If the LLM produces a drug name not present in the original patient record, the dashboard flags it with an "unverified entity" marker. Graph citations are validated against the actual subgraph output — any LLM claim not traceable to a retrieved edge is marked uncertain.

§7 — Safety + Explainability

Safety & Explainability

Two parallel systems. One deterministic — never overridable. One probabilistic — always auditable. Together they ensure every clinical suggestion is both safe and explainable.

Deterministic Layer

Rule-Based Safety Gates

  • MAP < 65 mmHg → immediate RED alert, AI inference blocked
  • SpO₂ < 90% → oxygen emergency flag raised before LLM runs
  • Lactate > 4.0 mmol/L → critical metabolic alert surfaced instantly
  • Drug contraindications checked against a hardcoded rule set — no model inference involved
  • Severity classification signed as a tamper-evident object before passing downstream
  • All rule firings written to audit log with timestamp and threshold values
severity_classifier.py · Stage 1 · no-LLM
Probabilistic AI Layer

Grounded AI Assistance

  • LLM suggestions cite specific PrimeKG graph nodes by name — not paraphrased
  • Every drug alert traces to a retrieved drug_disease or disease_disease edge
  • Guideline citations tagged with source document and chunk index
  • Uncertain inferences explicitly marked — model instructed to surface doubt
  • AI never acts autonomously — output displayed for physician review only
reasoner.py · citation-aware · physician-in-loop

Full Traceability Chain

Graph Traceability
Every LLM mention of a drug or disease is validated against the actual subgraph retrieved for that patient. Unvalidated claims are flagged with an ⚠ unverified entity marker.
Explainability
The physician sees the exact graph edges that triggered a drug alert — not a black-box score. "Metformin → Kidney Failure" is shown as a named edge, not a probability.
Fallback Behaviour
If entity linking fails (similarity < 85%), the system skips graph context for that entity and flags it as unlinked. The suggestion still runs but carries a reduced-confidence marker.
Audit Trail
Every inference cycle writes: patient ID, timestamp, severity result, retrieved guideline chunks, subgraph node list, and AI suggestion hash. Immutable. Physician-reviewable.
§8 — Failure Modes + Resilience

Failure Modes & Resilience

Every system fails. The question is whether it fails safely. Each failure mode below has a known response — tested, documented, and logged.

LLM Timeout or OOM
↓ System Response
Deterministic severity result is surfaced immediately. AI suggestion is marked "unavailable — check deterministic alert". No crash. No silent failure.
Entity Linking Failure
↓ System Response
Drug or disease name below 85% match threshold is excluded from graph traversal. A "no graph context" flag is appended to the prompt. The LLM is instructed to note this explicitly.
FAISS Index Corrupt or Missing
↓ System Response
Guideline retrieval is skipped. Inference continues with graph context only. No error surfaced to the physician — just a "guideline retrieval unavailable" note in the trace log.
PrimeKG Graph Not Loaded
↓ System Response
System falls back to guideline-only retrieval. All drug interaction alerts are suppressed and replaced with a "graph unavailable — manual review required" warning displayed to the physician.
LLM Hallucinated Drug Name
↓ System Response
Post-inference validation checks all drug names in the output against the original patient record. Unrecognised names are flagged with ⚠ unverified entity — never silently passed to the physician.
FHIR Parse Error
↓ System Response
Partial patient state is flagged as incomplete. Severity classification runs on available vitals only. AI inference is deferred until complete data arrives. A parse-failure alert is shown on the dashboard.
"A system that fails silently is more dangerous than one that fails loudly. Every failure mode here surfaces a visible, traceable signal — never a clean screen that hides a broken inference."
§9 — Future Infrastructure

Future Infrastructure

Six directions. Each grounded in a real clinical need — not a feature wishlist. None require cloud.

Horizon 1

HL7 FHIR Live Feed

Replace the static synthetic patient loader with a live HL7 FHIR R4 websocket feed from real hospital EMRs. Zero change to downstream layers — the PatientState interface remains the same.

Horizon 2

Multi-Patient Ward Mode

Extend the severity-sorted grid to a full ward — 12–24 patients, all processed in parallel. Priority queue triggers AI inference for RED patients first. GREEN patients are polled on a 5-minute cadence.

Horizon 3

Federated Graph Updates

Allow hospitals to contribute local drug interaction observations to a federated update layer — without sharing patient data. PrimeKG edges are weighted by local clinical evidence. Privacy-preserving by design.

Horizon 4

Temporal Reasoning

Add time-series awareness to the graph traversal — tracking how a patient's condition graph evolves over hours. Detecting early deterioration patterns before vitals breach threshold rules.

Horizon 5

Regulatory Compliance Layer

Add a formal audit export in DICOM-SR and HL7 Clinical Document Architecture format. Full inference trace, physician decision log, and uncertainty markers packaged for MDR and FDA SaMD review.

Horizon 6

Hardware-Optimised Inference

Port the reasoning layer to run on a dedicated on-premise NVIDIA L40S or AMD MI300X. Sub-500ms end-to-end inference. No cloud dependency. No HIPAA surface area outside the hospital perimeter.
